# Migrating from EdgeRum 2.x to 4.0.0

**Install the EdgeTelemetry backend release before shipping any app built
with EdgeRum 4.0.** The backend release covers deployment, analytics,
processor and collector. A 4.0 build no longer copies the app identity
onto every event, so a backend that predates contract 4.0.0 would lose it.

Host Swift code changes in one place: the `endpoint` you pass to
`EdgeRumConfig`. Everything else is a wire change the backend absorbs.
There is no 3.x release.

---

## Compatibility

|                             | Old backend                                          | New backend                                       |
|-----------------------------|------------------------------------------------------|---------------------------------------------------|
| **2.x SDK + legacy key**    | works (today)                                        | works: app inferred, legacy path `/collector/telemetry` |
| **2.x SDK + app-bound key** | n/a (no app-bound keys)                              | works: app from the key, no envelope check        |
| **4.0 SDK + legacy key**    | **unsupported** — app identity lost                  | works: app inferred from the envelope `app`       |
| **4.0 SDK + app-bound key** | **unsupported**                                      | works: the target setup                           |

---

## What's changing

**Public Swift API**

- `EdgeRumConfig.endpoint` is the **full collector URL**, used exactly as
  given. The SDK no longer appends `/collector/telemetry`.
- `EdgeRumConfig.location` and `EdgeRumConfig.environment` (and the
  `Environment` type) are deprecated and ignored. Nothing is sent for them.

**Delivery**

- A batch the server rejects with a 4xx other than 429 is dropped: never
  retried, never queued. Batches already in the offline queue follow the
  same rule when they are replayed, so one rejected batch no longer blocks
  the batches behind it.
- 429, 5xx and network errors are retried (immediately, +2 s, +8 s, +30 s;
  `Retry-After` honoured up to 60 s), then queued offline. Unchanged.

**Wire payload** — contract 4.0.0; see the CHANGELOG for the full list.

- The batch carries the app, SDK and device identity once, at its root.
  Events no longer repeat `app.*`, `sdk.*` or `device.id`.
- No `location` or `environment` anywhere.
- The batch `timestamp` is the send time; queued batches are re-stamped.

---

## Why

- **Endpoint as given.** A reverse proxy usually mounts the collector
  under its own prefix (for example `/collector-go/telemetry`). Appending a fixed path produced a URL that
  did not exist, the server answered 404, and the SDK dropped the data.
  Posting to the URL you configure works behind any proxy layout.
- **4xx never queued.** A request the server rejected will be rejected
  again. Keeping it at the head of the queue stopped every later batch.
- **Environment from the key.** The backend derives the environment from
  the API key, so a per-app setting could only disagree with it.

---

## Wire format impact

**Yes.** Contract 4.0.0. Rollout order:

1. Install the backend release (deployment, analytics, processor,
   collector).
2. Issue an app-bound API key per environment (below).
3. Ship the 4.0 app build.

## Public API diff

```swift
// Before — 2.x: a base URL; the SDK appended /collector/telemetry
var config = EdgeRumConfig(
    apiKey: "edge_…",
    endpoint: URL(string: "https://collect.example.com")!
)
config.environment = .production

// After — 4.0.0: the full URL, used as given; no environment
let config = EdgeRumConfig(
    apiKey: "edge_…",            // one app-bound key per environment
    endpoint: URL(string: "https://collect.example.com/collector-go/telemetry")!
)
```

---

## Manual changes needed

- **Set the full endpoint URL.** If you configured a base URL and relied
  on the SDK appending `/collector/telemetry`, append your collector's
  path yourself. For the standard deployment that is
  `https://<host>/collector-go/telemetry`. To keep posting to the legacy
  path, configure `https://<host>/collector/telemetry` — the collector
  keeps it as a permanent alias — but prefer the standard path.
- **Request an app-bound API key per environment** (production, staging,
  …) from the backend and ship the matching key in each build. The SDK no
  longer sends an environment; the key decides it. Drop any
  `config.environment` and `config.location` assignments (they compile,
  with a deprecation warning, and do nothing).
- **Dashboards / queries** that read `app.*` or `sdk.*` from individual
  events read them from the batch instead; the backend does this for you.
