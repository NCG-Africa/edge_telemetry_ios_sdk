# Privacy and App Store

What EdgeRum touches, what it never touches, and how to satisfy App
Review.

## Overview

EdgeRum is designed to be App-Store-reviewable out of the box. It does
not use the IDFA, does not trigger the App Tracking Transparency
prompt, does not import `AdSupport`, and ships a privacy manifest in every
distribution slice. The manifest is currently the F1 stub; its
restricted-reason declarations land with F20.

## Identifiers

EdgeRum owns three identifiers, all generated locally:

| Identifier   | Storage                                     | Notes |
|--------------|---------------------------------------------|-------|
| `device.id`  | Keychain (`com.edge.rum.identity`)          | `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`. UserDefaults fallback when Keychain writes fail. iOS clears Keychain on uninstall on modern installs — `device.id` rotates on reinstall in practice. |
| `session.id` | UserDefaults suite `com.edge.rum.session`   | Rotates after 30 minutes of inactivity or on cold start. |
| `user.id`    | UserDefaults suite `com.edge.rum.session`   | SDK-owned anonymous id. `EdgeRum.identify(_:)` attaches host-app `user.name` / `user.email` / `user.phone` as additional attributes but **does not** change this id. |

All three carry 8 bytes of `SecRandomCopyBytes` entropy as 16 hex
characters: `device_<epochMs>_<16 hex>_ios`,
`session_<epochMs>_<16 hex>_ios`, and `user_<epochMs>_<16 hex>` (no
`_ios` suffix). They are never sent to advertising networks; they are
never persisted to iCloud Keychain.

## User identity controls

- ``EdgeRum/identify(_:)`` attaches `user.name`, `user.email`,
  `user.phone` and your own user id to later events, verbatim — no
  hashing or truncation. Calling it is your assertion that you have the
  user's consent.
- ``EdgeRum/clearUser()`` detaches that profile. Call it on logout:
  `identify(_:)` merges, so it cannot express "a different person" on
  its own.
- ``EdgeRum/resetIdentity()`` generates a new `device.id` and `user.id`
  and detaches the profile. Wire it to a user's data-deletion request;
  delete the old ids on your backend.
- ``EdgeRum/disable()`` is the consent lever: it halts capture and
  sending, and keeps already-queued files on disk. It also stops hang
  detection, and ``EdgeRum/enable()`` does not restart it — hang
  detection returns on the next launch.

The profile fields are kept in memory only. They are not written to the
crash-recovery file, so a crash reported on the next launch carries
`user.id` but not the name, email, or phone.

## Restricted-reason APIs

The restricted-reason APIs the SDK calls, and the declarations the
manifest will carry once F20 lands. The shipped manifest is still the
F1 stub with an empty `NSPrivacyAccessedAPITypes` array, so host apps
must declare these reasons themselves in the meantime:

| API category | Reason code | Why we use it |
|--------------|-------------|---------------|
| File timestamp APIs | `C617.1` | Offline queue file housekeeping |
| System boot time   | `35F9.1` | Uptime for `page_load` |
| Disk space         | `E174.1` | `device.freeStorage` context |
| UserDefaults       | `CA92.1` | Session, user, and consented-location persistence |

App Store Connect now validates the merged manifest of the host app
plus every SDK. The SDK ships its own manifest at
`Sources/EdgeRum/Resources/PrivacyInfo.xcprivacy`; Xcode picks it up
automatically for SwiftPM and CocoaPods consumers. XCFramework
consumers can copy the manifest into their app bundle or rely on
Xcode's merging during archive.

## IDFA / ATT

EdgeRum does **not**:

- Import `AdSupport` or read `ASIdentifierManager.advertisingIdentifier`.
- Trigger `ATTrackingManager.requestTrackingAuthorization`.
- Read the device serial number, MAC address, or vendor identifier
  intended for cross-app tracking.

The SDK's anonymous `device.id` and `user.id` are local random values
generated by `SecRandomCopyBytes`. They do not provide cross-app
linkability, and they survive only as long as the host app's Keychain
and UserDefaults containers do.

## What we send

Every event carries a flat `attributes` map of primitives only —
`String`, `Int`, `Double`, `Bool`. Request and response headers,
cookies and bodies are never read. HTTP requests are recorded with
their full URL today, query string included; use
``EdgeRumConfig/sanitizeUrl`` to strip sensitive query parameters and
path segments. A future release drops the full URL and keeps only host
and path.

Taps are labelled with the control's `accessibilityIdentifier`. A
button's on-screen title is used only when you opt in with
``EdgeRumConfig/captureButtonTitles``; taps that land in a secure text
field are never recorded.

The SDK never contacts a location provider and never sends the device
IP to a third party. To tag batches with a location, set
``EdgeRumConfig/location`` yourself.

Every key that may appear on the wire, with its personal-data class,
and the list of identifiers the SDK never collects, live in the
[data catalogue](https://github.com/NCG-Africa/edge_telemetry_ios_sdk/blob/main/docs/catalogue/ios-data-catalogue.md).

## Data retention and the offline queue

When the live transport cannot reach the backend, batches spill to
files under `Library/Caches/edge-rum/queue/` for later replay. The
cache directory is not backed up to iCloud and is purged by the OS
under storage pressure; the queue is capped at
``EdgeRumConfig/maxQueueSize`` (default 200 events) with oldest-file-
first overflow. The only other file is
`Library/Caches/edge-rum/last-session.json`, which holds the current
session, device and anonymous user ids so a crash can be attributed on
the next launch.

## Sample privacy disclosure

If the host app maintains its own privacy disclosure, the EdgeRum
section can read:

> *EdgeRum collects anonymous performance data — frame render times,
> network request timings, screen names, taps, lifecycle transitions,
> native crash reports, and connectivity changes — to help [host app]
> diagnose performance and stability issues. No advertising or
> cross-app tracking identifiers are collected, and no personal
> information is captured unless the host app explicitly calls
> `EdgeRum.identify(_:)` with values it has obtained with user
> consent. Data is sent to [host app's backend] under [host app's
> retention policy].*

Adjust to match your own retention, your own user-identity flow, and
your backend's hosting region.
